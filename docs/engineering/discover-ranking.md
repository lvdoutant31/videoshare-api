# 首页热门与搜索排序

## 热门排行

使用最近 7 个自然日的播放、当前有效点赞/收藏、正常且未删除的评论。
每天向前衰减 20%，当天系数为 1，昨天为 0.8，以此类推。
播放按 `video_watch_daily` 的 UTC 日期计算；互动和发布时间使用数据库存储时间。

先对各项次数加权累加，再计算热度：

`ln(1 + 播放) + 3 × ln(1 + 点赞) + 4 × ln(1 + 收藏) + 2 × ln(1 + 评论)`

同分按发布时间降序、ID 降序。历史累计互动不会直接带来热门加分。
首页前 4 个位置取热度最高内容；第 5 个位置优先选择近 3 天发布、尚未入选的内容，
新内容中仍按热度、发布时间排序。无候选新内容时补入热度第五名，内容不足 5 条时不重复填充。
全部候选沿用公开、已发布、审核通过、未删除/下架、作者正常及媒体可用的过滤条件。
图文每次打开详情计播放的规则保持不变，本轮没有新增访客级去重。

## 搜索

`GET /api/v1/app/discover` 保留 keyword/categoryId/tagId/limit，新增：

- `sort`：`COMPREHENSIVE`（默认）、`LATEST`、`HOT`。
- `page`：从 1 开始；limit 默认 24，最大 50，C 端每页请求 20 条。
- 响应新增 `page`、`hasMore`，保留已有数据字段。

综合排序优先级：标题完全匹配、标题前缀匹配、标题包含、启用标签包含；
同级按热度、发布时间、ID 排序。最新按发布时间/ID，最热按热度/发布时间/ID。
所有模式仍限制在关键词与分类/标签匹配的候选中。百分号、下划线按字面关键词匹配。

C 端把排序写入 URL，更换关键词、分类、标签或排序后重置到第一页。
“加载更多”追加下一页，失败保留已加载结果并重试相同页；返回详情后保留结果和滚动位置。
热门实时变化会移动分页边界，当前前端按 ID 合并去重，未建立排序快照。

## 验证和发布

MySQL 集成测试覆盖相关性优先、显式最新/最热、分页边界、字面关键词、参数校验、
热度衰减、历史累计量不加分、近期新内容位置、下架和私密过滤。
前端单元与手机/桌面浏览器测试覆盖排序切换、加载更多/失败重试、URL 重载和详情返回。
本轮无需数据库迁移。Windows 发布仍使用 `deploy/build-release.ps1` 和 BAT 服务安装流程。
