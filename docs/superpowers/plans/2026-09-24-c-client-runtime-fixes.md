# C 端运行时问题修复实施计划

**目标：** 修复推荐流 422、开发代理埋点噪声、资料保存与个人统计不同步、评论回复消息缺失以及视频无封面问题，并用前后端测试验证关键链路。

**范围：** 后端 `ticktok-api` 与 C 端 `yingliu-c`。保留现有账号密码登录、真实姓名注册、联系管理员重置密码等既有改动。

## 任务 1：游标与开发代理容错

- 调整 C 端分页请求构造：没有游标时完全省略 `cursor` 参数，避免向后端发送 `cursor=`。
- 为推荐流及同类分页接口补 URL 单元测试。
- 将前端埋点改为环境变量显式启用；开发环境默认不发送批量埋点，生产环境仍可通过 `VITE_ANALYTICS_ENABLED=true` 开启。
- 核对 Vite 代理目标和后端监听端口，保留清晰的本地启动说明。

## 任务 2：资料保存与个人统计

- 将资料编辑页改为标准表单提交，确保点击保存只触发一次 `PATCH /api/v1/app/me`，并在用户信息异步恢复后正确回填。
- 保存成功后用接口返回值更新认证状态；进入“我”页面时重新拉取 `/app/me`。
- 检查点赞、关注关系的写入逻辑；个人页统计改为数据库实时聚合或在写操作中可靠维护，避免缓存计数漂移。
- 增加资料保存和统计变化的前后端测试。

## 任务 3：评论回复消息与站内回复

- 增加评论回复通知持久化结构，记录收件人、回复人、视频、被回复评论、新评论、摘要、已读状态和时间。
- 发布回复时为被回复评论作者创建通知（排除给自己发通知），并保证评论与通知在同一事务中落库。
- 增加分页查询回复通知、标记已读接口。
- 将 C 端消息页整合为“评论回复 / 视频分享”，评论回复卡片可直接输入并调用现有发表评论接口回复。
- 增加通知生成、查询和前端回复调用测试。

## 任务 4：视频封面

- 先复用媒体处理链路中已有封面字段；有封面时统一输出可访问 URL。
- 对历史数据或处理失败导致的空封面，C 端使用统一的设备品牌占位图，并在可播放组件中使用视频首帧/海报渐进替换，避免空白或破图。
- 覆盖推荐流、发现列表、作者/个人视频列表和消息视频卡片。
- 增加空封面映射测试和页面渲染检查。

## 任务 5：验证

- 后端：运行相关单元/集成测试与 Maven 编译；若 Testcontainers 因 Docker 未运行而跳过，明确记录。
- 前端：运行单元测试、构建和关键 Playwright 场景。
- 核对浏览器控制台：无空游标 422；后端未启动时开发环境不再主动发送埋点请求；资料保存、计数刷新、消息回复和封面均有可见结果。
