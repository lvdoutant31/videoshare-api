# 映流短视频系统数据库设计

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 数据库 | MySQL 8.0 / InnoDB / utf8mb4 / UTC 存储时间 |
| 上游依据 | PRD V1.1、产品原型、技术选型 V1.0 |
| 建模范围 | V1 业务表、审计表、任务表、日级统计表与埋点事件分表策略 |

## 1. 建模约定

- 主键统一使用 `BIGINT UNSIGNED` 雪花 ID，由应用生成；不使用自增 ID，便于后续服务拆分。
- 业务时间统一使用 `DATETIME(3)`，应用层以 UTC 写入，展示时按用户或运营端时区转换。
- 所有表使用 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci`。
- 可审计的主业务对象采用逻辑删除：`deleted`、`deleted_at`、`deleted_by`。关系表和原始事件表可物理删除或按保留策略归档。
- 枚举值用 `VARCHAR` 保存，由 Java 枚举约束，避免数据库 `ENUM` 难以演进的问题。
- 手机号、企微成员 ID、IP、设备标识等敏感数据不建立明文可检索字段：手机号保留加密密文和用于精确匹配的 HMAC 摘要；后台只读取脱敏值。
- `created_by`、`updated_by` 为操作者账号 ID；系统/异步任务写入时为 `0`。

## 2. 领域关系概览

```text
sys_user ──< sys_user_wecom_identity
    │  ├──< video >── video_media_resource
    │  ├──< video_comment ──< video_comment
    │  ├──< user_video_like / user_video_favorite / user_follow
    │  ├──< user_video_history / video_share_inbox
    │  └──< content_report / user_penalty
    │
video ──< video_audit_record / video_publish_schedule / video_stats
      ──< video_category_map >── content_category
      ──< video_tag_map >── content_tag

sys_admin_user >── sys_admin_user_role >── sys_role >── sys_role_permission >── sys_permission
```

## 3. 身份、会话与权限

### 3.1 手机端用户 `sys_user`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED PK | 用户 ID |
| `phone_ciphertext` | VARBINARY(512) | 加密手机号，可空 |
| `phone_hmac` | CHAR(64) UK | HMAC-SHA-256 摘要，用于精确匹配，可空 |
| `nickname` | VARCHAR(64) | 昵称 |
| `avatar_media_id` | BIGINT UNSIGNED | 头像媒体资源，可空 |
| `bio` | VARCHAR(256) | 简介 |
| `status` | VARCHAR(24) | `NORMAL` / `MUTED` / `SUSPENDED` / `BANNED` / `CANCELLED` |
| `mute_until` | DATETIME(3) | 禁言到期，可空 |
| `suspend_until` | DATETIME(3) | 临时封禁到期，可空 |
| `violation_count` | INT UNSIGNED | 累计违规次数 |
| `like_received_count` | BIGINT UNSIGNED | 获赞聚合值 |
| `following_count` | BIGINT UNSIGNED | 关注数聚合值 |
| `follower_count` | BIGINT UNSIGNED | 粉丝数聚合值 |
| `last_login_at` | DATETIME(3) | 最近登录时间 |
| `deleted` | TINYINT(1) | 逻辑删除标记 |
| `deleted_at/deleted_by` | DATETIME(3)/BIGINT | 注销或删除记录 |
| `created_at/updated_at` | DATETIME(3) | 创建、更新时间 |

索引：`uk_phone_hmac(phone_hmac)`；`idx_status_created(status, created_at DESC)`；`idx_nickname(nickname)`。

用户注销后将 `nickname` 替换为匿名展示名、清空或加密隔离资料，并将 `status` 置为 `CANCELLED`；依法保留的安全、审计和交易记录不得随用户资料一起删除。

### 3.2 企微身份映射 `sys_user_wecom_identity`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED PK | 映射 ID |
| `user_id` | BIGINT UNSIGNED | 平台用户 |
| `corp_id` | VARCHAR(128) | 企微企业 ID |
| `wecom_user_id_ciphertext` | VARBINARY(512) | 加密企微成员 ID |
| `wecom_user_id_hmac` | CHAR(64) | 成员 ID HMAC 摘要 |
| `display_name` | VARCHAR(128) | 同步的展示名，可空 |
| `bind_status` | VARCHAR(24) | `ACTIVE` / `UNBOUND` |
| `bound_at/unbound_at` | DATETIME(3) | 绑定与解绑时间 |
| `created_at/updated_at` | DATETIME(3) | 创建、更新时间 |

约束：`UNIQUE(corp_id, wecom_user_id_hmac)` 保证一个企微成员只能绑定一个平台账号；`UNIQUE(user_id, bind_status)` 在应用层保证每个平台账号只能保留一个有效绑定（MySQL 对软状态唯一性需配合事务校验）。

### 3.3 后台账号与 RBAC

| 表 | 核心字段 | 约束与索引 |
| --- | --- | --- |
| `sys_admin_user` | `id`、`username`、`password_hash`、`status`、`user_id`（可关联手机端账号）、`last_login_at` | `uk_username(username)`；密码仅存 Argon2id/bcrypt 哈希 |
| `sys_role` | `id`、`role_code`、`role_name`、`status`、`is_system` | `uk_role_code(role_code)`；系统角色不得物理删除 |
| `sys_permission` | `id`、`permission_code`、`permission_name`、`resource_type`、`resource_path`、`parent_id`、`sort` | `uk_permission_code(permission_code)`；类型：`MENU/PAGE/BUTTON/API` |
| `sys_admin_user_role` | `admin_user_id`、`role_id`、`created_at` | `pk(admin_user_id, role_id)` |
| `sys_role_permission` | `role_id`、`permission_id`、`created_at` | `pk(role_id, permission_id)` |

后台账号状态：`NORMAL`、`DISABLED`、`LOCKED`。登录失败次数与锁定期放 Redis，避免高频写库；密码重置、角色变更、停用均写入 `sys_audit_log`。

### 4.2 视频主表 `video`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED PK | 视频 ID |
| `author_id` | BIGINT UNSIGNED | 作者（首期由运营指定） |
| `title` | VARCHAR(120) | 标题 |
| `description` | VARCHAR(2000) | 简介 |
| `source_note` | VARCHAR(128) | 音乐/来源说明，可空 |
| `cover_media_id` | BIGINT UNSIGNED | 封面资源 |
| `original_media_id` | BIGINT UNSIGNED | 原始视频资源 |
| `audit_status` | VARCHAR(24) | `DRAFT` / `TRANSCODING` / `PENDING_REVIEW` / `APPROVED` / `REJECTED` / `REVISION_REQUIRED` |
| `publish_status` | VARCHAR(24) | `UNPUBLISHED` / `SCHEDULED` / `PUBLISHED` / `OFF_SHELF` / `DELETED` |
| `visibility` | VARCHAR(24) | `PUBLIC` / `PRIVATE` / `DESIGNATED`（V1 预留） |
| `risk_level` | VARCHAR(16) | `NONE` / `LOW` / `MEDIUM` / `HIGH` |
| `manual_weight` | INT | 运营人工权重，默认 0 |
| `scheduled_at/published_at/off_shelf_at` | DATETIME(3) | 生命周期时间 |
| `off_shelf_reason` | VARCHAR(512) | 下架原因，可空 |
| `current_version` | INT UNSIGNED | 编辑版本，用于审核记录关联 |

索引：

- `idx_feed(publish_status, audit_status, visibility, published_at DESC)`：推荐候选初筛。
- `idx_author_status(author_id, publish_status, published_at DESC)`：作者主页。
- `idx_audit_queue(audit_status, risk_level DESC, updated_at ASC)`：审核队列。
- `idx_schedule(publish_status, scheduled_at)`：定时发布扫描。

公开读取必须同时满足 `audit_status=APPROVED`、`publish_status=PUBLISHED`、`visibility=PUBLIC`、`deleted=0` 和作者 `status=NORMAL`。

索引：`idx_user_active(user_id, status, ends_at)`、`idx_expiry(status, ends_at)`，由定时任务处理到期恢复。

## 7. 异步任务与数据统计

### 7.1 异步任务 `sys_async_task`

Redis Stream 是任务传输通道，此表记录可查询、可重试、可人工补偿的任务状态。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED PK | 任务 ID |
| `task_type` | VARCHAR(48) | `TRANSCODE` / `COVER_GENERATE` / `PUBLISH` / `COUNTER_AGGREGATE` / `NOTIFICATION` / `MEDIA_BACKUP` |
| `business_type/business_id` | VARCHAR/BIGINT | 幂等业务键 |
| `payload` | JSON | 非敏感任务参数 |
| `status` | VARCHAR(24) | `PENDING` / `PROCESSING` / `SUCCEEDED` / `RETRYING` / `FAILED` / `CANCELLED` |
| `retry_count/max_retries` | INT | 重试计数与上限 |
| `next_retry_at` | DATETIME(3) | 下次重试时间 |
| `last_error_code/last_error_message` | VARCHAR | 脱敏错误摘要 |
| `started_at/finished_at` | DATETIME(3) | 执行时间 |
| `created_at/updated_at` | DATETIME(3) | 创建、更新时间 |

约束：`uk_task_idempotency(task_type, business_type, business_id)`；`idx_poll(status, next_retry_at, created_at)`。

### 7.2 日级指标 `daily_metric`

| 字段 | 类型 | 说明 |

### 7.3 原始行为事件 `analytics_event_YYYYMM`

原始事件按月建表，当前月表由迁移脚本提前创建。表结构相同：

| 字段 | 类型 | 说明 |
| --- | --- | --- |

| `event_name` | VARCHAR(64) | PRD 事件字典中的事件名 |
| `occurred_at` | DATETIME(3) | 客户端发生时间（受服务端校正） |

## 9. 迁移、归档与容量策略

1. 使用 Flyway 管理迁移，命名为 `VyyyyMMddHHmm__description.sql`；禁止 `ddl-auto=update`。
2. 启动时仅执行结构迁移和必要基础数据（权限、系统角色、配置键），生产环境中的运营数据不由应用启动脚本覆盖。
3. `analytics_event_YYYYMM` 在每月前七天由任务创建下月表；创建失败必须告警。事件表超过 180 天执行归档，归档前先验证日级指标已完成。
4. `sys_audit_log`、`sys_login_log` 和任务失败记录至少保留 180 天；具体时长在上线前依法律与审计要求确认。
5. 所有外键服务于核心一致性；行为事件、日志与高写入量统计表不使用外键，避免写入与归档阻塞。
6. 大表按表而非一开始分库分表。单月事件表、审计表达到容量阈值后，先归档，再评估分区或分析库迁移。

## 10. 首批基础数据

- 系统角色：`SUPER_ADMIN`、`OPERATOR`、`REVIEWER`、`CUSTOMER_SERVICE`。
- 权限应覆盖菜单、页面、按钮和接口四个层级；高风险权限包括永久封禁、不可恢复清理、批量下架、密钥配置与角色授权。
- 系统配置键至少包括：上传文件大小/时长限制、允许 MIME、上传暂停阈值、媒体根目录标识、备份状态、评论开关、敏感词策略、举报原因、企微企业与应用配置、分享落地页域名及协议版本。

## 11. 待实现时确认

1. 用户 ID、后台账号 ID 是否都采用 Snowflake；当前建议统一采用。
2. 手机号加密/HMAC 密钥的托管方案（首期应用环境变量或受控密钥文件，生产应使用专用密钥管理机制）。
3. 媒体资源是否允许 SHA-256 去重；默认只建查询索引，不做自动去重，避免权限与生命周期耦合。
4. 数据保留期限、账号注销匿名化规则与审计日志不可篡改的具体合规要求。
